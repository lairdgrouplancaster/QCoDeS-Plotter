# qPlot bug investigation · 17 November 2026

Eight application defects were independently reproduced on Windows. Two can silently mislead someone using an exported file. A standalone database can depend on the author's original NetCDF file, and a frozen-slice CSV can give correct numbers the wrong units. The database-safety probes found no violation of the source-file invariant. Application fixes await review.

## Confirmed findings

### 1. A successful standalone database export can omit the measurements

A recipient can open the copy and see the run, yet have no access to its recorded values.

- **Reproduce.** In QCoDeS 0.63.0 make a catalogue with one ordinary SQLite run and one `DataSetInMem` run whose only raw data is exported as NetCDF. Use **File → Export All Runs as Database** or select just the NetCDF-backed run and use **Export Selected Runs as Database**. Take the new database away from the original `.nc` and reopen the run by GUID with QCoDeS.
- **Expected.** qPlot rejects a standalone export that would depend on a separate raw-data file. The user guide explicitly gives that restriction.
- **Observed.** Both commands reported success. In the independent replay the external run returned `[-1, 8, 71, 736]` while its original NetCDF was reachable. After moving the disposable NetCDF directory, the external run returned `{}` with a missing-raw-data warning. The embedded run in the same all-runs copy still returned `[11, 8, 23, 88]`. Discovery also reproduced this with both trusted and snapshot copy paths.
- **Source.** `src/qplot/datahandling/database_export.py:122` checks for `raw_data_db_path`. The genuine NetCDF-backed catalogue lacked that column. An embedded control with an optional NetCDF export remained independently readable, so the mere presence of a NetCDF export path does not identify the defect. Contract in `docs/user-guide.md:879`.
- **Evidence.** Database discovery `external.py`; independent File-menu reproduction `test_external_replay.py::test_standalone_replay`, log `external3.log`.

### 2. Frozen-slice CSV can assign the wrong units to every row

An analysis that trusts the machine-readable units can interpret a derivative as an unprocessed measurement or assign coordinates to the wrong physical dimensions.

- **Reproduce.** Open a 3D measurement with differently dimensioned axes. Freeze the displayed slice, swap X and Y in the frozen window, select the X derivative, apply it, then export the displayed heatmap to CSV.
- **Expected.** The CSV's `x_unit`, `y_unit` and `value_unit` agree with the exported columns and the current plot.
- **Observed.** The independent replay froze axes in seconds and teslas with values in watts. After the swap and derivative, the GUI showed `T, s, W/T`, and all nine numbers matched the analytical derivative of −2 W/T. Each CSV row still said `s, T, W`. The axis-unit error already occurred after the swap alone. The first investigator obtained the same defect with Hz, mV and nA.
- **Source.** `src/qplot/windows/_volume_cut.py:506` captures the original metadata and `:525` reuses it during CSV capture. The original unit fields come from `src/qplot/windows/plot3d.py:860`.
- **Evidence.** `test_measure.py::test_frozen_export_units`; independent `test_volume_crosscheck.py::test_frozen_swap_and_derivative` and `crosscheck-frozen.json`.

### 3. Selected-run database export can reject an entirely self-contained selection

An unrelated external run prevents the user from sharing the embedded runs they selected.

- **Reproduce.** Use the mixed catalogue from finding 1. Select only an ordinary SQLite-backed run and choose **Export Selected Runs as Database** with a new destination.
- **Expected.** The new database contains the selected run, its measurements and metadata, and opens independently. The unselected external run is outside the export scope.
- **Observed.** The export failed with `no such table: results-1-1` for the independent writer's external-first catalogue. No destination appeared. Reversing run order moved the error to `results-1-2`. Both copy paths failed, and the discovery investigator also reproduced the failure when an unselected run used QCoDeS's separate-SQLite backend. A selected embedded-only control exported and reopened even after its optional NetCDF file was moved.
- **Source.** `src/qplot/datahandling/database_export.py:37` collects result table names for excluded runs and `:47` drops them in the private copy. An externally stored run can have a recorded table name with no corresponding local table. Contract in `docs/user-guide.md:887`.
- **Evidence.** `external.py`, `mixed_sqlite.py`; independent `test_external_replay.py`, including the embedded-only control.

### 4. A 3D slice fails to open when complex array records change precision

Valid QCoDeS measurements can become unviewable even when all values and coordinates are finite and exactly representable at both precisions.

- **Reproduce.** Register an array output with three real setpoints. Write two array rows in one depth plane, one `complex64` and the other `complex128`. Open the 3D plot in Re or Im mode.
- **Expected.** The chosen component renders at the recorded coordinates. For the small Im case the expected grid was `[[2, 7], [-5, 0]]`.
- **Observed.** The viewer showed **Plot load failed**. The worker raised `TypeError: float() argument must be a string or a real number, not 'complex'`. Refresh repeated it. The independent writer verified the stored array dtypes, reversed their order and reproduced the failure. Its homogeneous 64-bit and 128-bit controls both displayed the expected nine cells. The guide explicitly includes complex QCoDeS arrays in higher-dimensional plots at `docs/user-guide.md:489`; older wording at `:820` is inconsistent with that section and with the working controls.
- **Source.** `src/qplot/datahandling/volume.py:184` builds an object array for a mixed batch. The complex check at `:191` sends it through the real matrix path at `:196`, which reaches `src/qplot/tools/general.py:61`.
- **Evidence.** `test_mixed.py::test_mixed_complex_width_volume`; independent `test_volume_crosscheck.py::test_accepted_array_precision` and `crosscheck-width-complex128-complex64.json`.

### 5. A valid 64 px preference makes snapshot previews repeat indefinitely while open

The selected preview stays at **Generating preview...** and qPlot keeps issuing work for an image it has already computed.

- **Reproduce.** Open a QCoDeS database in snapshot fallback, select a run with a 1D measurement and type `64` into **Preferences → Preview image size**. Keep the selection unchanged.
- **Expected.** The selected image appears at 64 px and the queue drains, as it does at 63 and 65 px.
- **Observed.** The first investigator stopped after eight successful notifications. The independent investigator obtained fallback with a real retained rollback journal and observed twelve successful notifications, a cached thumbnail, two active workers and no full preview. Changing to 65 or 66 px restored the images and drained the work. Quit during the loop also retired the workers.
- **Source.** `src/qplot/windows/_preferences.py:549` permits 50–1000 px. `src/qplot/windows/_widgets/preview.py:971` infers the job's purpose from its width. A full preview at the fixed thumbnail width takes the thumbnail branch and schedules another preview at `:984`.
- **Evidence.** `test_qt_ownership.py::test_snapshot_preview_size`; independent `test_independent_ui.py::test_replay` and `replay_receipt.json`.

### 6. A transient thumbnail error leaves a snapshot preview pending with no work

A temporary read failure can leave the user waiting after the condition has cleared. Reselecting the run and pressing Refresh give no indication that a retry is needed.

- **Reproduce.** In snapshot fallback at the normal 200 px preference, let metadata settle. During a new preview generation, make one selected thumbnail read fail, then restore access. Select a different run, return to the original, switch tabs and refresh.
- **Expected.** The selected pane displays a failure or recovers on retry. A generating status corresponds to active or queued work.
- **Observed.** The independent investigator briefly held the disposable rollback journal with Windows read sharing denied. After access was restored, there was still only one attempt, no full preview, zero active or queued jobs and a visible **Generating preview...** message. Reopening the database or changing the size recovered the images. The recorded data and journal stayed intact.
- **Source.** `src/qplot/windows/_widgets/preview.py:975` stores the thumbnail error. The display check at `:1019`, selection handling at `:564`, and queue guard at `:858` leave that state in place.
- **Evidence.** `test_qt_ownership.py::test_transient_thumbnail_failure_reselection`; independent `test_independent_ui.py::test_replay` and `replay_receipt.json`.

### 7. A cut through a complex array loses the original value in the cursor readout

Someone inspecting a recorded point on the cut sees only its chosen component. The plotted component and its exported numerical value are correct.

- **Reproduce.** Store a 3D complex array against real setpoints. Choose Im, open a horizontal cut from the slice and hover a known point. Compare with the parent slice and with the same measurement recorded as scalar complex values.
- **Expected.** The cursor retains the original complex value and setpoints, as documented in `docs/user-guide.md:499`.
- **Observed.** For a recorded `39+21i`, the parent and scalar-backed control retained both components. The array-backed horizontal cut showed only `2.10000e+01`. A vertical cut in Re mode showed only `39`. The first investigator independently observed `37` for `7+37i`. Both investigators checked the projected display and CSV.
- **Source.** `src/qplot/windows/_volume_cut.py:54` captures original complex samples only for a parameter declared `complex`. QCoDeS declares the container `array` when it holds complex array values.
- **Evidence.** `test_measure.py::test_complex_volume_cut_cursor`; independent `test_volume_crosscheck.py::test_cursor` and `crosscheck-cursor-array-h.json`.

### 8. CSV from a frozen slice cut omits the fixed in-plane coordinate

Two cuts at different physical coordinates can produce identical files. Even with the original database, a recipient cannot identify which cut was exported when the values coincide.

- **Reproduce.** Open a 3D run, freeze one slice and take a horizontal cut at a known row of the frozen image. Export its CSV. For a control, export the same cut from the live slice. No operation or axis swap is needed.
- **Expected.** The frozen cut export identifies both fixed coordinates, as the cut annotation does. The guide promises fixed coordinates on slice/cut CSV exports at `docs/user-guide.md:828`.
- **Observed.** The discovery cut retained its fixed depth of 3 T and all three values but omitted the fixed bias of 31 mV. The independent investigator created equal-valued traces at 11 and 79 mV in a 9 K slice. The two frozen windows displayed the correct, distinct annotations. Their complete CSVs were byte-identical. Equivalent live-cut CSVs carried the respective voltages and unit in the `cut` column. The description of a frozen snapshot as an ordinary 2D plot at `docs/user-guide.md:807` was considered. The exported files expressly include the original 3D provenance and the guide gives no frozen-cut exception to the fixed-coordinate requirement.
- **Source.** `src/qplot/windows/_volume_cut.py:535` determines the fixed axis and coordinate. Lines 540–542 put that coordinate in the on-screen description and pass the plane's metadata to the line. At `:568`, line CSV capture reuses that metadata.
- **Evidence.** Coordinator `test_frozen_cut.py::test_fixed_coordinate_in_cut_csv`, `frozen-cut.json`; independent `test_cut_replay.py` and `cutreport.log`.

## Cross-feature workflows

**Zoom during live refresh.** A real QCoDeS writer committed an initial 9 × 9 map, then a second measurement at each of four coordinates. We held submission of the real refresh worker, changed the viewport to 2.9–4.1 on both axes, scheduled the viewport reload, then released the worker. The final axes were 3 and 4 on each dimension. The displayed means and exported CSV both gave `[[83, 84], [93, 94]]`. The visible resolution warning described these same four displayed cells, eight in-range source rows and the committed viewport. Source artefacts matched between writer steps.

A second ordering held delivery of a real, completed full-view refresh, appended two measurements, then requested two different zooms with the resolution dialogue open. Before delivery, the dialogue kept the previous 81-row report. After delivery, it showed the latest X range 1.9–3.1, Y range 3.9–5.1 and six source rows. The visible grid and CSV both gave `[[1342, 1043], [1052, 1353]]` at the four expected coordinates.

**Switch database during export.** A and B each had run ID 1, distinct GUIDs and distinguishable signals. With an A plot open, we started **Export All Runs as Database**, paused the task on a real copy-progress notification, loaded B, selected the pending A export in the export list and cancelled it. B's browser retained its own GUID and reader. A's plot retained its original GUID and reader, then displayed the new A value 135 after the writer appended it. B's plot yielded `[-100, -93, -86, -79, -72]`. The destination never appeared and the export child retired. Closing the last A plot retired A's reader while B's reader remained open. Closing B retired its reader. Both sources passed the protected-file checks. A second run paused the real child inside backup as well as its parent's progress callback. The switch itself set the cancellation flag before the explicit Cancel action. While that cancellation was pending, the same child still held read-only handles to A's main and WAL and held no B handles. After releasing the callback it exited. Cancelling the export a second time was harmless. The switch initiates cancellation in `src/qplot/windows/_database_actions.py:1766`.

**Stale callbacks and shutdown.** A finished B load was held until C was selected, then delivered. The browser, plot and exported CSV retained C's values `[910, 913, 916, 919]`. All three readers closed, the plot's native widget was deleted and the window reached shutdown with zero remaining plot workers. A separate delayed snapshot preview delivered an older ramp after the newer square waveform was displayed. The newer pixels and GUID survived, the old worker retired, and reopening the first source reproduced the ramp.
